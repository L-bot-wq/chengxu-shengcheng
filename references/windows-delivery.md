# Windows 桌面交付参考

## 架构选择

1. 检查 Windows 版本、CPU 架构、已有工具链和目标电脑的实际权限；在用户需求和可维护性之间选择合适的原生框架或受支持的 WebView 壳。
2. 对简单本地桌面工具，可比较 WinUI/WPF/.NET、PySide、Tauri 等。框架选择是工程决策，不要保证某框架在全部机器可用。不能把浏览器网页、PyInstaller 打包或 WebView 统一冒充“原生无依赖”。
3. 面向用户的入口应明确：桌面快捷方式、开始菜单或独立应用窗口。开发模式和最终发行模式分别检查，不要求用户运行开发命令。

## 文件和升级

- 稳定的用户数据与程序安装目录分开，参考系统用户数据目录或明确提供可移动数据目录。首次运行、权限受限和位置变更时提供可恢复的错误提示。
- 定位桌面快捷方式目标及运行实例；已有程序升级前只读核对目标、旧文件/版本、数据路径与锁定情况。备份用户数据和拟修改文件，优先原子写入并支持失败回滚。
- 同一台机器上多副本容易分叉；说明快捷方式实际指向、正在升级的版本及状态。不要仅更新开发目录并称实际副本已更新。若系统权限禁止原位置写入，准备一步可执行更新或用户可选择的可写安装位置并说明需要其操作。
- 不更改无关的快捷方式、系统全局配置或默认浏览器。启动或关闭服务仅影响本程序拥有的实例，退出策略要能处理崩溃和后台窗口。

## 外观和图标

- 为程序提供独立应用图标，生成高质量矢量稿或高分辨率原稿，并按 16、24、32、48、64、128、256 像素提供 Windows ICO。检查小尺寸可辨识性，必要时微调小图标细节。
- 在 EXE 资源、快捷方式、窗口及任务栏验证图标；不要因 ICO 内包含多个尺寸就声称用户桌面任务栏显示正确。缩放、置顶和窄窗需实际验证。
- 若系统或执行环境不支持图形化测试，交付时直说测试边界，提供具体步骤供用户验证。

## 分发

- 验证目标系统安装包或便携目录的依赖、启动、路径含中文/空格、重启持久化、复制/移动、升级、导出、备份和还原。
- 开源组件依许可分发。校验压缩包/可执行文件可打开且包含必要资源。数字签名、SmartScreen、管理员权限、系统组件只按实际情况说明，不要承诺不存在的能力。
- 若使用本地 WebView 或服务，绑定回环地址；控制授权、窗口来源、退出和失败处理；仅在明确需要手机共享时启用网络监听。
