# GitHub 工作流

- 检查当前连接的账号及目标仓库，读取仓库可见性、默认分支、权限和现有说明。用户指定的仓库是边界，不擅自向其他仓库写入。
- 将通用技能源和新生成的应用项目区分。除非用户指定同一仓库，应用默认建立独立项目或在任务目录开发；技能仓库只包含可复用的技能定义、参考资料和必要脚本，不放本人的账单、模型、图片或构建临时文件。
- 处理现有仓库时先看状态和历史，保留用户已有内容，不执行强制推送、覆盖或删除。按任务授权选择私有/公开、分支和发布方式。
- 检查忽略规则，至少排除用户数据、凭证、日志、缓存和未要求纳入的生成物；开发者令牌不打印、不写入文件或源码。
- 使用当前环境支持的连接方式。连接了 GitHub 账号不代表所有仓库均可访问，也不代表本地技能已安装或程序已自动更新。每一步以实际工具返回结果和远端文件校验为准。
- 若用户要求更新/安装技能，遵守当前环境技能管理流程；若因为权限或网络失败，保留可审阅内容并如实说明，不能自称已安装。
